# MikroTik sync regressions

Run `npm run test:e2e:mikrotik-sync -- --headed` to observe the fixed flows. Set `MKS_E2E_SLOW_MO=700` to slow browser actions. The runner prints its artifact directory; videos, screenshots, sanitized expected/actual JSON, and an HTML report are retained there. The two original correctness tests and the explicit whole-company/mobile regression now pass. The original failing evidence is retained in the specification workspace.

- **FT033-13:** CP has two router-only clients on different networks. Filter by `visible-only-client`, select its one row, and import as own client. Correct: only that client is created. Original defect (now fixed): `all_import=true` and an empty UUID list cause both visible and hidden clients to be imported. The browser opens `/clients` to show the result; a fresh database snapshot verifies persisted ownership and the untouched MK sentinel.
- **FT033-14:** MK has Router A and Router B packages sharing `shared-gold`. Router A's package is inserted first. Resolve Router B's existing client's mismatch. Correct: assign Router B Gold (BDT 800). Original defect (now fixed): Router A Gold (BDT 3,000) is assigned. The browser opens `/clients` to show the package; a fresh database snapshot verifies package and client network IDs.

The runner follows the existing fund-report acceptance harness: real Next.js pages/server actions and Laravel HTTP kernel, a disposable SQLite `:memory:` connection, fresh application scopes per request, generated credentials, registered `cp.isp.test` / `mk.isp.test` hosts on an ephemeral port, scratch build/storage, fake notifications and HTTP, and an in-memory router adapter that reports fixture clients offline without opening any router connection. Bulk jobs are dispatched by the real controller and executed through their real handlers against the disposable DB. This serialized fixture does not prove production queue concurrency.

Browser contexts are isolated by test and authenticate through the UI. No saved sessions, local MySQL records, real routers, or application runtime files are changed. Trace recording is off to keep session tokens out of artifacts; videos show masked login inputs and synthetic fixture data. `MKS_E2E_ARTIFACT_DIR` selects the report directory and `MKS_E2E_CHROMIUM` optionally selects an existing Chromium executable.

The root `test:e2e` runner includes this config and starts its fixture automatically. A normal focused run now exits zero. The final correctness assertions remain in place to catch regressions. FT033-15 additionally verifies that whole-company import requires an explicit scope choice, defaults to selected rows, and fits a 390px mobile viewport.
