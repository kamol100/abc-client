# Mandatory Playwright agent instructions

Applies to all Playwright tests, fixtures, helpers, setup and specifications in this directory. Read the root constitution first, then [initial test guidelines](specifications/INITIAL-TEST-GUIDELINES.md), [coverage policy](specifications/COVERAGE-POLICY.md), and the feature ticket before writing tests.

- Browser login MUST use registered local tenant hosts. Never authenticate against localhost:3000, localhost:3001 or 127.0.0.1 as a fallback.
- Company tenants: http://cp.isp.test/admin (cp) and http://mk.isp.test/admin (mk). Their authenticated company_id scopes normal business data. SMS send uses http://vp.isp.test/admin (vp, username vpc) and MK as the other company.
- Administration: http://app.isp.test/admin (kamol). Authorized platform workflows may intentionally read/manage other tenants; hostname or company_id alone grants no permission.
- Credentials live in ignored .env.e2e.tenants.local. Never hardcode passwords in specs/docs, print secrets, or commit generated sessions.
- Standard npm run test:e2e runs every root-level playwright*.config.ts suite, including all client projects, invoices, support tickets, and legacy tests. Invoice checks use `npm run test:e2e:invoices` and `playwright.invoices.config.ts`. It continues after a failing suite and returns failure if any suite fails. Isolated client mutations require their documented fixture controls; do not silently exclude them from the full command. Add future feature configs at the root with distinct test/report directories. Focused suites have separate npm scripts. Support tickets use `npm run test:e2e:tickets` and `playwright.support-tickets.config.ts`. Reseller checks use `npm run test:e2e:resellers` and `playwright.resellers.config.ts`. Network checks use `npm run test:e2e:networks` and `playwright.networks.config.ts`. SMS send checks use `npm run test:e2e:sms-send` and `playwright.sms-send.config.ts`. Confirm is never clicked, because that queues a message. Expense checks use `npm run test:e2e:expenses` and `playwright.expenses.config.ts`. Staff checks use `npm run test:e2e:staffs` and `playwright.staffs.config.ts`. Disposable staff are created and deleted in that suite. Existing staff are not locked, reset, or deleted. Platform support uses `npm run test:e2e:platform-support` and `playwright.platform-support.config.ts`; it does not collect the legacy support-ticket specs. Image and thread mutations stay in the isolated project and fail until a disposable fixture file is supplied. Use playwright.clients.config.ts for the CLIENT-001 suite: it explicitly loads tenant keys and uses host/persona-isolated in-memory sessions. The preexisting default playwright.config.ts/helpers remain separate and must not be assumed tenant-aware.
- Referral acceptance uses `npm run test:e2e:referrals` and `playwright.referrals.config.ts`. The runner supplies generated credentials and a disposable SQLite Laravel fixture, starts a scratch Next.js instance, and uses app/cp/mk registered hosts on an ephemeral port. It verifies seller enrollment, attribution, commission approval, payouts, role denial, identity changes, and mobile/localized states. See `tests/e2e/referrals/README.md`. The root runner starts this fixture automatically for the referral config.
- Verify exact host, authenticated dashboard and expected identity/permissions after login. Remaining on /admin, HTTP200 or cookie existence alone does not prove success.
- Never reuse session storage across hosts/personas or use app administration credentials to satisfy a company-isolation test.
- Missing host/backend/profile/permissions is a fixture/environment failure; report it instead of changing host, swallowing auth errors or weakening assertions.
- Use approved company A/B fixtures for isolation tests and authorized/unauthorized platform personas separately. Never assume platform cross-tenant access must always fail.
- Read backend contracts; use semantic locators, independent test data, safe cleanup, controlled external integrations and fresh persistence assertions.
- Preserve preexisting edits, record actual commands/results, update coverage register only with real evidence, and finish with .ai/report.md.

- Fund report acceptance uses `npm run test:e2e:fund-reports` and `playwright.fund-reports.config.ts`. Its runner starts a disposable SQLite Laravel fixture and scratch Next.js on registered CP/MK/APP hosts. See `tests/e2e/reports-funds/README.md`. Never point this fixture at local MySQL.
- Product acceptance uses `npm run test:e2e:products` and `playwright.products.config.ts`. The runner starts a scratch Next.js application and a disposable in-memory Laravel fixture on registered CP/MK hosts with generated credentials. It never mutates the existing local stock/funds/database. See `tests/e2e/products/README.md`; its serialized HTTP broker does not prove real MySQL concurrency.
